# 🔒 Secure Tax Assistant — Local Privacy Gateway & RAG Organizer

A full-stack, **privacy-first** portfolio project that simulates the core workflows of a secure tax intake operation: PII redaction before LLM processing, multi-year tax organizer generation via a local LLM, real-time sales-assistant trigger lookup, and automated document ingestion with live progress tracking.

Built to demonstrate secure AI workflow design aligned with **FTC Safeguards Rule** and **IRS Publication 4557** data-protection principles.

---

## 🏗️ Architecture

\`\`\`mermaid
graph TD
    UI[React + Vite Frontend] -->|HTTP| API[FastAPI Backend]
    API --> PG[Privacy Guardrail Layer]
    API --> DB[(SQLite: tax_clients.db)]
    API --> RET[Retrieval Pipeline]
    RET --> DB
    RET --> PG
    PG --> OLL[Ollama — Local LLM]
    OLL -->|Markdown Organizer| API
    API -->|JSON| UI
\`\`\`

### Layers

| Layer | Responsibility |
|---|---|
| **Frontend** (React + Vite) | 4-tab UI: Organizer, Trigger, Upload, Progress |
| **API** (FastAPI + Uvicorn) | Routing, validation (Pydantic), CORS, business logic |
| **Privacy Guardrail** (\`privacy_guard.py\`) | Regex-based PII detection & redaction (SSN, phone, email, bank, DOB, ZIP, DL) with audit logging |
| **Storage** (SQLite) | Clients, tax years, document checklists — all local, no external DB |
| **Retrieval** (\`retrieval.py\`) | Queries SQLite, scrubs PII, formats payload for LLM |
| **AI Generation** (Ollama + \`rag_organizer.py\`) | Local LLM generates structured Multi-Year Tax Organizer in markdown |

## ✨ Features

| Tab | What it does |
|---|---|
| 📄 **Organizer** | Fetches a client multi-year tax organizer generated by the local LLM (Ollama) from real database records |
| 📞 **Trigger** | Type a phrase (\"audit notice\", \"missing W-2\") → get prioritized next steps + list of outstanding docs |
| 📎 **Upload** | Simulate document ingestion; updates checklist status from Missing → Received; demonstrates PII redaction on document text |
| 📊 **Progress** | Live progress bar + full checklist table with status badges and \`received_at\` timestamps |

## 🔐 Privacy-First Design Decisions

1. **Local-only LLM.** No data leaves the machine. Ollama runs \`llama3\` locally; no cloud API calls.
2. **Defense-in-depth PII redaction.** \`privacy_guard.py\` is called at two independent points:
   - In \`retrieval.py\` (scrubs the profile before it enters the prompt)
   - In \`rag_organizer.py\` (hard gate on the final assembled prompt before Ollama sees it)
3. **Audit logging.** \`redact_pii_with_audit()\` returns every finding (type, original value, position) for compliance traceability.
4. **No external database.** SQLite is a single local file — no network exposure, no credentials to leak.
5. **Client tokenization.** The LLM prompt references clients as \`CLIENT-0001\`, never by name or SSN.

### PII Patterns Detected

| Pattern | Regex (simplified) | Replacement |
|---|---|---|
| SSN (dashed) | \`\\\\d{3}-\\\\d{2}-\\\\d{4}\` | \`[REDACTED_SSN]\` |
| SSN (plain) | \`\\\\d{9}\` (bounded) | \`[REDACTED_SSN]\` |
| Phone | \`555-123-4567\` variants | \`[REDACTED_PHONE]\` |
| Email | \`user@domain.tld\` | \`[REDACTED_EMAIL]\` |
| Bank/Account | 8–17 consecutive digits | \`[REDACTED_ACCOUNT]\` |
| Date of Birth | \`MM/DD/YYYY\` | \`[REDACTED_DOB]\` |
| ZIP Code | 5 or 5+4 digits | \`[REDACTED_ZIP]\` |
| Driver\\'s License | \`XX-1234567\` | \`[REDACTED_DL]\` |

> **Production escalation path:** Replace regex engine with [Microsoft Presidio](https://github.com/microsoft/presidio) for NER-based, context-aware detection (full names, addresses, entity resolution).

## 📄 Document Gathering Solution

The document-gathering bottleneck (target: **30% reduction** in time-from-signed-client-to-complete-documentation) is addressed by the simulated ingestion pipeline:

1. **Upload Simulation** — \`POST /upload-document/\` accepts a document name + optional raw text.
2. **PII Scrub** — Raw text passes through \`privacy_guard.py\` before any preview is returned.
3. **Database Sync** — Checklist status flips from \`Missing\` → \`Received\` with a UTC timestamp.
4. **Progress Feedback** — \`GET /client/{id}/status\` returns a percentage the frontend renders as a live progress bar.
5. **Trigger Lookup** — When a client mentions a missing doc on a call, the agent gets instant next steps + the exact outstanding list.

This maps directly to a production pipeline of: Secure Portal Upload → OCR/Classification → Compliance Scrub → DB Sync → AI-Driven Follow-Up.
